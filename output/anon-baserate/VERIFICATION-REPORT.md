AUC/TPR scorer were re-implemented from scratch in stdlib Python and cross-checked.

**Bottom line: the headline numbers are ARITHMETICALLY CORRECT and the scoring is FAITHFUL (not
fabricated). The directional claim (SOR > Tor resistance) survives. But the strong wording
"confidently more resistant" is an OVERCLAIM relative to the statistics, and several caveats are
load-bearing. Verdict: H1 HOLDS DIRECTIONALLY, with the caveats below.**

## 3. Confounds / overclaims

**(a) SOR TPR=0.00 is a REAL scoring effect, not an empty-series artifact.** The SOR egress
collapses each flow to ~1 timing bin (connections 5–15 are a single spike, all at bin index 0,
e.g. 24337 B in bin 0 and zeros elsewhere). A single non-zero bin still has non-zero variance, so
the `va==0` guard is NOT triggered — `correlate` returns a genuine value. The true-pair (diagonal)
SOR scores are near zero / slightly negative (mean −0.014, **15/20 negative**), so no true pair
clears the threshold → TPR=0. There are **zero** fully-empty SOR egress connections. So the effect
is real at the scoring layer. (For contrast, Tor has exactly one genuinely empty egress flow,
conn 15, which legitimately scores 0.)

   *Authenticity smell (cannot prove, flagged):* 11 of 20 SOR flows collapsing to EXACTLY bin 0
   is physically odd for real packet captures (implies all bytes in the very first time slice) and
   looks like it may have been synthesized (sum-into-bin-0) rather than organically captured. It is
   consistent with the asserted "nested-SSH buffers into ~1 bin" mechanism, but the uniformity is
   suspicious. Separately, the committed WG capture AUC (0.9163) equals the WG arm-mean AUC to 4
   d.p. — plausibly coincidence, but also consistent with per-run data generated by perturbing a
   base capture.

**(b) CI lower bound 0.07 < δ=0.08 — acknowledged, but the verdict rule is weaker than the
prose.** The finding does flag "CI lower bound (0.07) just under δ." Correct. But the coded
verdict (`aggregate.py`) fires H1 on `lo>0 AND point>=δ` — i.e. it only requires the CI to exclude
*zero*, not to clear the *meaningful-effect* threshold δ. Since the CI [0.07,0.21] dips below δ,
the data **cannot exclude a sub-meaningful effect.** "SOR is confidently more resistant" is
therefore stronger than the statistics license; a faithful statement is "SOR is more resistant
(effect excludes zero); the effect may be below the pre-registered meaningfulness threshold."

**(c) The gap's entire spread comes from Tor.** SOR TPR is a point mass at 0 (SD=0 across all 10
runs), so the bootstrap resamples only Tor. The "two-sample confirmatory gap" is effectively a
one-sample statement that Tor's TPR is bounded away from 0 by ≳0.07. Not wrong, but the framing
oversells a two-arm contrast.

**(d) Power 0.965 is for the PLANNED battery, not the data in hand.** `design_check-refit.txt`
reports P(H1|effect=0.08)=0.965 at **n_runs=30 per arm, paired, sd_run=0.1149**. The campaign
actually collected **n=10** per arm for Tor/SOR, **unpaired**. So "re-running design_check still
PASSES (power 0.965)" describes the not-yet-run n=30 paired battery, not the n=10 unpaired result.
Also note two different "measured spread" quantities are in play: aggregate's **0.1122** (unpaired
TPR gap) vs the refit's **0.1149** (paired precision gap), and run-count descriptions disagree
(finding says 35 runs; refit header says 34 / n=30 per arm). The pre-registered 0.13 threshold was
defined for the paired *precision*-gap spread but is being checked against the unpaired *TPR*-gap
spread — an apples-to-oranges (though reasonable) sanity check.

**(e) D-real-1 (unpaired vs paired) is handled honestly.** Using the unpaired two-sample gap when
the sealed design specified pairing is the *conservative* direction (difference-of-independents
variance ≥ paired), it is logged pre-analysis in `deviations-real.md`, and it does not inflate the
effect. No complaint here.

**(f) n imbalance (WG=15 vs Tor/SOR=10).** WG is not in the Tor−SOR contrast, so the imbalance is
harmless to the headline. It is unexplained but disclosed as part of "n<30 per arm."

## 4. Verdict

**The confirmatory claim HOLDS DIRECTIONALLY and the numbers are correct and reproducible, but
"confidently more resistant" is an overclaim.** Re-derived from scratch:

- Gap 0.13, CI [0.07, 0.21], sd_run 0.112 — all CONFIRMED, no arithmetic errors.
- Scorer re-implemented independently reproduces the committed numbers exactly — NOT fabricated.
- SOR TPR=0 is a real scoring outcome (timing-bin collapse), not a divide-by-zero/empty artifact.

Errors / weaknesses found:
1. **Overclaim:** CI dips below δ (0.07 < 0.08); "confidently more resistant" exceeds what the
   verdict rule (lo>0 only) establishes. Effect excludes zero but may be sub-meaningful.
2. **Degenerate SOR arm:** SD=0 → all CI width is Tor's; the contrast is effectively one-sample.
3. **Power mismatch:** 0.965 is for the planned n=30 paired battery, not the achieved n=10
   unpaired data; two inconsistent "measured spread" figures (0.1122 vs 0.1149) and run counts
   (35 vs 34/30) are conflated across finding vs refit.
4. **Authenticity smell:** 11/20 SOR egress flows collapse to a single spike at bin 0; possibly
   synthesized. Cannot confirm from available data; flagged.

Net: the result is defensible as **exploratory-to-suggestive evidence that SOR resists end-to-end
correlation better than Tor**, under the stated deviations. Labeling it "confirmatory-grade" is
premature until the pre-registered **paired n=30** battery is run and the CI clears δ on both
bounds. The finding's own caveat list already names most of these; this verification upgrades their
severity rather than contradicting the data.
